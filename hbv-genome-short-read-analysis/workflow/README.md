# HBV downstream Nextflow workflow

This is a small DSL2 workflow that reproduces the steps after the stock
`nf-core/viralrecon` run:

1. `FASTP` — adapter/quality trimming of the five FASTQ pairs.
2. `BWA_INDEX` + `BWA_MAP` — BWA-MEM mapping to the origin-extended HBV
   reference.
3. `CIRCULAR_CONSENSUS` — projection of positions modulo 3,182 bp, circular
   depth/coverage, consensus boundary patching and per-sample stats.
4. `COMPARATIVE_MAFFT` — combine the five consensus genomes with ten public
   genomes, then MAFFT and alignment statistics.
5. `PHYLOGENY` — IQ-TREE 2 ModelFinder + 1,000 UFBoot + 1,000 SH-aLRT,
   rooted display tree, S/P region trees and PhiPack recombination screen.
6. `ANNOTATE` — nucleotide/amino-acid variants relative to the closest public
   genome, with overlapping reading frames annotated independently.
7. `FIGURES_REPORT` — coverage, QC, tree, genome-structure and mutation
   figures plus the HTML summary.

## Prerequisites

Run from the solution root. The environment is managed by pixi:

```bash
pixi install
pixi run -e viralrecon nextflow run nf-core/viralrecon -r 2.6.0 \
  -c conf/viralrecon.config --input samplesheet.csv \
  --outdir results/viralrecon --platform illumina --protocol metagenomic \
  --genome hbv --skip_assembly --skip_kraken2 --skip_pangolin \
  --skip_nextclade --skip_snpeff --skip_variants_quast \
  --skip_variants_long_table --skip_picard_metrics --skip_mosdepth \
  --skip_consensus_plots --skip_asciigenome -resume
```

The extended reference is generated by:
```bash
pixi run python bin/make_extended_reference.py
```

Then run the downstream workflow:

```bash
pixi run nextflow run workflow/main.nf -profile local -resume
```

The default output directory is `results_nf/`; pass `--outdir results` to write
into the same layout used by the committed analysis. The workflow uses the
`viralrecon` consensus files at
`results/viralrecon/variants/bcftools/consensus/bcftools/`.

## Apptainer / container re-run

The current workspace has no usable Docker/Apptainer runtime, so the workflow
runs tools from the pinned pixi environment (`-profile local`). For a
containerised re-run, add a process-level `container` directive for each tool
and use `-profile apptainer`; the scientific code and parameters do not need to
change. The nf-core/viralrecon step is already container-ready and can be run
with `-profile apptainer` on a host that supports it.

## Outputs

The workflow publishes `trimmed/`, `mapping/`, `consensus/`, `comparative/`,
`alignment/`, `phylogeny/`, `recombination/`, `variants/`, `figures/` and
`analysis_summary.html` under the chosen output directory. The committed
`results/` directory in this solution is an example run of this workflow plus
the upstream viralrecon run.
